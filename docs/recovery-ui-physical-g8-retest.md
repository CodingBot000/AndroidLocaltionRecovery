# PR #9 G8 실기기 역순 내구 재시험

## 비교 범위

2026-11-27 KST에 SM-G975N(Android 12/API 31, Exynos 9820, ARM64)에서 A `a732af2dddfb86514fbfa76a6d7971f31e8d23da`와 C `ce617de21ffbf5485564c9d7bc589a3b6085c02c`의 내구를 재시험했다. 시작 PR head는 `85cced17da60c6fc7e700676d1e662cdd6a26e7f`였다. 시작 전 잠금이 해제돼 있었고 런처를 전면으로 돌린 뒤 이전 G9의 홈 화면 복원을 확인했다. G9 GPS·수명 계측은 추가하지 않았다.

최초 G8의 A→C 결과는 독립 기록으로 보존하고 이번 시험은 C→A 순서로 수행했다. 제품 Debug APK 두 파일은 최초 G8에서 사용한 것과 바이트 단위로 일치했다. 각 소스의 격리 worktree에서 테스트 전용 `PhysicalOsmEnduranceTest`에 유휴 300초와 600초 표본만 추가해 계측 APK를 새로 빌드했다. O10 1× 180초·Reset 10회 및 기존 60초·120초 유휴 표본과 단언을 유지했다. 각 빌드의 10회 주행과 유휴 관측을 합쳐 독립 내구 실행 한 번으로 계산한다. [최초 G8 결과](recovery-ui-physical-g8.md) · [최초 데이터](benchmarks/sm-g975n-pr9-g8.json)

동일 SM-G975N과 USB, 화면 1,080×2,280·density 420·60Hz·글꼴 1.1, 허용된 비행기 모드 ON·Wi-Fi OFF를 사용했다. C의 계측 직전 온도를 기록한 뒤 A 준비 후 초기 온도 차이가 1.0°C 이내가 되도록 대기했다. 기존 APK 6개, 계측 미디어 13개, 단말 설정·권한의 사본과 해시를 보존했다. `install -r`로 기존 사용자 데이터 디렉터리를 유지했다.

## 판정 기준과 집계

각 실행의 같은 PID에서 기록한 `Debug.MemoryInfo`의 전체·Native Heap·Dalvik PSS 및 Graphics와 `Runtime`의 Java 사용 힙을 비교한다. 완료 중앙값과 Theil–Sen은 2–10회 완료 표본을 사용한다. 새 최대값은 전체 600초 범위와 최초 시험과 동일한 120초 범위로 나눠 기록한다. 기준 대비 후보의 전체 또는 Native PSS가 기존 정의의 최대값·완료 중앙값·유휴 120초에서 10% 이상 증가하는지, 그리고 최초의 기울기 증가 방향이 반복되는지 확인한다. 확장 유휴 300·600초는 별도로 비교한다. 측정 중 강제 GC, 캐시 제거 또는 앱 프로세스 재시작을 하지 않는다.

## 분리 진단

Native PSS의 조사 기준 초과와 후보의 더 큰 상승 기울기를 확인한 뒤 장시간 내구와 별개로 A/C당 O10 180초 주행과 Reset을 한 번 수행했다. 두 제품 APK는 내구와 동일하며 진단 코드는 격리 worktree의 테스트 APK에만 추가했다. 지도 준비 후 Perfetto `android.heapprofd`로 65,536바이트 간격의 샘플링을 시작해 완료와 Reset을 관찰했다. 추적 종료 후 같은 프로세스에서 Reset 뒤 지도 준비 상태 및 Activity 종료 후 유휴 상태의 HPROF를 요청했다. `am dumpheap`의 `-g` 옵션은 사용하지 않았다. Shark 2.14로 지도·재생·Activity 객체의 GC root 경로를 조사했다. [Perfetto 할당 샘플링](https://perfetto.dev/docs/data-sources/native-heap-profiler) · [Android 12 heap dump 구현](https://android.googlesource.com/platform/frameworks/base/+/refs/tags/android-12.0.0_r34/core/java/android/app/ActivityThread.java#6165)

| 분리 진단 | A | C |
|---|---:|---:|
| 마지막 완료 프로파일의 추정 미해제 `libc.malloc` (bytes) | 55,640,064 | 59,768,832 |
| 마지막 Reset 프로파일의 추정 미해제 `libc.malloc` (bytes) | 55,508,992 | 59,572,224 |
| 위 Reset 값 중 `libhwui.so` 포함 스택 (bytes) | 55,246,848 | 58,916,864 |
| Reset 뒤 root에서 도달한 `MapWorld` / `ReplaySession` | 1 / 1 | 1 / 1 |
| Reset 뒤 root에서 도달한 Compose `AndroidPath` | 2,144 | 2,143 |
| Activity 종료 후 유휴 heap의 `MainActivity` / `MapWorld` / `ReplaySession` | 0 / 0 / 0 | 0 / 0 / 0 |

두 빌드 모두 완료에서 Reset으로 갈 때 추정 미해제 malloc 양이 줄었다. Reset 표본에서는 후보 쪽에 약 3.88MiB가 더 있었고, 양쪽 모두 대다수가 `libhwui.so`를 포함한 스택이었다. 이 값은 지도 준비 뒤 기록한 샘플링 malloc 추정치다. 장시간 내구의 2–10회 할당 수명, 유휴 600초의 실할당량, GPU/드라이버 메모리 및 할당자 보유 페이지의 기여도는 이 진단에서 확인할 수 없다.

Reset 뒤 `MapWorld`는 Compose 슬롯의 `PreparedMapSlot.world` 경로에서, `ReplaySession`은 활성 Activity의 ViewModel을 거치는 경로에서 확인됐다. Activity 종료 약 59초 뒤 A/C 모두 `MainActivity`, `MapWorld`, `MapGeometry`, `ReplaySession`이 heap snapshot에 없었다. 양쪽에 남은 `LabViewModel` 하나는 계측 스레드가 잡고 있었고, A에 남은 Compose `AndroidPath` 하나는 Material3 슬라이더 경로였다. 중첩 객체의 root 경로는 상위 객체가 함께 선택될 때 일부 생략되므로 `MapWorld`, `ReplaySession`, Compose `AndroidPath`는 타입별 검색도 수행했다. 관측한 경로로 장시간 Native PSS 차이의 원인을 확정할 수 없다. [진단 수치, root 경로와 원본 해시](benchmarks/sm-g975n-pr9-g8-retest.json)

## 판정과 복원

**장시간 기능 내구 PASS · G8 최종 INCONCLUSIVE.** 두 비교에서 후보의 Native PSS 완료 기울기가 더 컸다. 역순에서는 최대값과 완료 중앙값이 10% 조사 기준을 넘었고 유휴 120초의 기준 초과는 재현되지 않았다. 분리 진단에서 활성 지도와 테스트가 쥔 객체를 확인했으며, 장시간 증가를 특정 할당, 누수, 또는 환경 탓으로 돌릴 근거는 확보하지 못했다. G3·G7·G9는 **INCONCLUSIVE**를 유지했다. [전체 수용 게이트](recovery-ui-validation.md#f7--기존-pr과-수용-게이트)

장시간 계측 종료와 분리 진단 종료 후 각각 원래 APK 6개와 계측 미디어 13개의 SHA-256을 확인했다. 앱 데이터 디렉터리·중지 상태·Live 중단 파일과 권한·위치 스위치·화면 및 네트워크 설정·보안 잠금 상태가 일치했다. 잠금 해제된 홈 화면으로 복원했다. 단말의 이번 시험 임시 파일은 내구 22개와 진단 62개를 로컬 사본과 해시 대조한 뒤 제거했다.

원본 계측 로그, 환경 및 복원 기록, APK, Perfetto trace와 HPROF는 Git에서 제외한 `build/reports/recovery-ui/pr9-g8-retest-20261127/`에 보존했다. 두 주행 비교에는 제외 실행이 없다. [최초 익명화 데이터](benchmarks/sm-g975n-pr9-g8.json) · [역순 익명화 데이터](benchmarks/sm-g975n-pr9-g8-retest.json)
